# Reusable idea-to-product prompt

Use $idea-to-product for the idea I provide. My default stack is Next.js App
Router, TypeScript, Tailwind and Firebase; use other services when justified and
tell me what accounts, costs or setup are needed. I prefer autonomous execution:
make routine decisions and finish concrete, reviewable work before asking me to
approve an external action. Ask focused questions when my answer changes the
product, and keep progressing on independent work.

## Discover and decide

Read the current repository, AGENTS.md and relevant references first. Identify
the intended customer, painful task, existing alternatives, smallest complete
journey and differentiating kernel. Write a candid feasibility assessment:
what can work, what is uncertain, what could make it fail and what evidence would
change that assessment. Verify time-sensitive claims and cite primary sources.

## Plan the product

Create or update scope.md, prd.md and spec.md. Define acceptance outcomes and
out-of-scope features. Design a distinctive landing page, accessible product
journey and clear errors. Model business rules and data boundaries before adding
integrations. Select Firebase services for actual needs, not as decorative stack
items. Record architecture, costs, privacy, security and operational decisions.

## Build and prove

Implement complete working slices, including server validation, deterministic
business logic, graceful provider failure, loading/empty/error states and mobile
layout. Add meaningful tests at risky boundaries and run the required checks.
Inspect the working result in a browser when available; save representative proof.
Track implementation decisions and test evidence without pretending unexecuted
checks passed. Use synthetic examples clearly labelled as examples.

## Prepare to operate

Review dependencies, secrets, access rules, abuse/cost limits, caching, security
headers, logging and data retention. Prepare CI, health checks, deployment settings
and a rollback/runbook. Test production mode locally, then the actual deployment
when account access permits. Separate software readiness from live operational
verification and any required professional review. Keep final personal/legal/account
actions with me where needed; never request secrets in chat.

## Explain the opportunity

Write a report covering practical obligations, failure risks, competition,
commercial hypotheses, operational cost drivers and validation experiments. Add
a prioritised future-features page that clearly distinguishes planned work from
available features. Show dependencies and why each addition helps a real user.

For a hackathon, verify its specific rules, deadline/timezone, required tools,
licensing and deliverables. Prepare a timed demonstration shot list and honest
judging analysis. Preserve my authorship where the event requires personal writing
or reflection. Do not manufacture provenance, backdate work or imply submission.

## Finish clearly

Give me the working result, how to run it, what changed, what passed, the report,
the roadmap and the concrete remaining setup. Complete all authorised work that
does not depend on missing information. Never invent product-market fit, a public
URL, account access, test results or a guarantee of winning. Reuse this process for
my later ideas only when I provide them.
